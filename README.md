# swift-file-cache

Use this package when something costly to make from a value should be read back by a later run, or another process, instead of being made again, and losing it now and then costs only the making. Start from `File.Cache`, made from the `File.Directory` its entries live in, and a `File.Cache.Key` holding a `FIPS_180_4.Digest` of everything that decides the bytes. `keep(_:for:)` keeps bytes under a key and `bytes(for:)` reads them back, or gives nil. The cache does not hash: what goes into a key is the caller's to decide, and it is the whole of the guarantee. If the bytes must outlive a crash or be kept for certain, this is the wrong package: write them with swift-file-system.

## Laws

- A key is a digest of every input that decides the bytes kept under it, including a version of whatever makes them. Two keys are the same entry exactly when their digests are equal; the cache cannot tell that bytes are stale, so whatever changes the bytes for the same inputs must change the key. A digest of any length FIPS 180-4 gives works; a SHA-256 key is the usual one.
- An entry is one file in the directory named by its key's `hex`, then `.entry`. It holds, in this order: the magic `FILECACH` (8 bytes), the entries' format as a little-endian 64-bit number (now 1), the key's digest, the payload's length as a little-endian 64-bit number, the payload's Adler-32 (RFC 1950) as a little-endian 64-bit number, then the payload. The header is 64 bytes for a SHA-256 key. A change to this layout raises the format, so entries of an earlier one are missed and remade.
- An entry that is missing, cut short, longer than its length says, of another magic or format, holding another key's digest, or whose payload does not match its Adler-32 is a miss: `bytes(for:)` gives nil and never throws. The Adler-32 finds damage by chance, not for certain, and an entry is a file anyone can write, so bytes read back are only as trusted as the directory; a caller that parses them must treat bad bytes as a miss too.
- `keep(_:for:)` makes the directory and its parents when needed, then writes the whole entry under a temporary name in the same directory and renames it into place, replacing what was there. A reader sees the old entry, the new one or none, never part of one, so processes may keep and read entries in one directory at once; the last rename wins. It does not wait for the disk: after a crash an entry may be missing or damaged, which is a miss. It throws `File.Cache.Error.directory` when the directory cannot be made and `.write` when the entry cannot be written; a caller that only caches may ignore both.
- Nothing is ever removed: entries stay until something else deletes them, and deleting any of them at any time is safe.
